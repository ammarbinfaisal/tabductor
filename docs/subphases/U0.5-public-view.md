## Scope

A link anyone can open that shows a workflow running. **Read-only, no interaction beyond
navigation and pagination.** Plus the owner-side surface for managing shares. NOT in scope:
assets (S5d/U3), run inspector detail (U1.5), anything that writes.

## Deliverables

1. **Extract, do not fork.** The public view renders the same three things the owner's view
   does, and if they are copies they will drift.
   - Lift the React Flow node/edge mapping out of `graph-editor.tsx` into a shared module
     that takes a graph and returns `{nodes, edges}`. The editor keeps its interaction
     (drag, connect, select); the public view renders the same mapping with
     `nodesDraggable`, `nodesConnectable` and `elementsSelectable` off.
   - Parameterize `runs-table.tsx` and `event-feed.tsx` by the fetcher they call, so owner
     and public differ only in which procedure is passed in. Their polling, pagination and
     rendering stay one implementation.
   - Do **not** reuse `editor-store.ts`. It is a mutation store; the public view gets its
     own small read-only store, so there is no code path from a public page to a mutation.

2. **Routes** (`apps/web/src/app/s/[token]/`), server components resolving the share and
   calling the public router through `createCaller`, as the owner's pages already do:

   | Route | Shows |
   |---|---|
   | `/s/<token>` | graph + live run summary |
   | `/s/<token>/runs` | runs table, keyset paginated |
   | `/s/<token>/runs/<id>` | one run: trigger, timings, error **class**, its emissions |
   | `/s/<token>/events` | event feed |
   | `/s/<token>/events/<id>` | one event: packet if public, lineage |

   Unknown, malformed and revoked tokens all render the same 404. Do not distinguish them
   in copy, in status code, or in how much work the page does before failing.

3. **Liveness:** `usePolling` at 2s, exactly as U0 does. No websockets, no SSE — the outbox
   owns the engine's latency budget and a second one on the read side is a second thing to
   debug. Historical browsing is the same procedures with a cursor; there is no archive
   path and no snapshot.

4. **Rendering rules (these are Threat 15, not style):**
   - Node names, event types and packet values come from LLM output and scraped pages.
     **No `dangerouslySetInnerHTML` anywhere in a public component**, no markdown renderer,
     no link auto-detection. Packet bodies render as text in a `<pre>`.
   - A private event renders its type and timestamp with an explicit "packet not shared"
     affordance — not an empty object, which reads as "the packet was empty".
   - A private lineage hop renders as a hop. Do not collapse it.

5. **HTTP posture** — set on every `/s/*` response (Next middleware or route segment
   config, whichever is less machinery):
   - `X-Robots-Tag: noindex, nofollow` — a share is unlisted; a crawler that indexes one
     has published it.
   - `Referrer-Policy: no-referrer` — the token is in the path, so without this any
     outbound click leaks it in `Referer`.

6. **Owner-side share management** on the workflow page:
   - Create → shows the plaintext link **once**, with a copy button and a plain statement
     that it will not be shown again, alongside the **visibility preview** S2d returns
     (the node names, event types and packet fields a viewer will read).
   - List existing shares by prefix and creation time; rotate; revoke with a confirmation
     that says what revoking does.
   - A `public` toggle per declared emit in the node config panel, writing
     `emits[].public` into the graph document. Because it is part of the document, turning
     it on is a graph change that goes through save/publish like any other — say so in the
     UI rather than making it look like a switch that takes effect immediately.
   - When a save changes the manifest, show the **diff** before publishing: which event
     types are becoming public, which are becoming private.

## Style constraints (binding)

- React hook policy holds: `useMountHook`, `useStoreBridge`, `usePolling` only. Server
  components by default; `"use client"` only where a component owns interaction.
- No new dependencies.
- No business logic in `apps/web`. If the public view wants a number the API does not
  serve, add it to S2d's read models with a system test — never compute it client-side
  over data that happens to be in hand, which is exactly how unmanifested data reaches a
  public page (§17.3).
- **No UI tests** (doctrine). S2d's system tests are the contract; this slice is verified
  by the backend suite plus eyes.

## Verification

```
pnpm install && pnpm build && pnpm test && pnpm --filter web lint
```

All prior tests stay green. Then, in a browser: seed a workflow, mark one of two emit types
public, save, create a share, open the link in a private window — confirm the graph renders
read-only, runs update live while the engine works, the public event's packet is visible,
the private one shows "packet not shared" with its hop intact, and a failed run shows a
class rather than a message. Revoke the share and confirm the same URL 404s on the next
load. Check the response headers for `noindex` and `no-referrer`.
